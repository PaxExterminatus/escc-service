🔴 Риски безопасности

Пароли клиентов хранятся и передаются в открытом виде

CLIENT.CLIENT_PASSWORD сравнивается как обычная строка без хеширования (REV_WEB_REQUEST.client_page_w). Восстановление пароля отправляет реальный пароль по email. Все параметры запроса, включая пароли, построчно логируются в текстовый файл на диске. → Рассылки: REV_WEB_REQUEST

SMTP-пароль в открытом виде в исходном коде

REV_EMAIL: smtp_password := 'fffa75Ms1' прямо в спецификации пакета — виден всем с доступом на чтение исходников схемы. → Рассылки: REV_EMAIL

FTP-пароль ЕРИП в открытом виде в исходном коде

ERIP: логин/пароль к ftp.hgrosh.by заданы константами в спецификации пакета. → Финансы: ERIP

Отключена проверка кода доступа к онлайн-курсу

APISAS_EFRONT.getonlineaccesscourse: IF TRUE THEN --access-px [...] — любой код принимается как верный. Для урока проверка осталась настоящей — непоследовательность. → API-слой: APISAS_EFRONT

Тестовые клиенты с вечным доступом и бэкдором сброса

ID 2333/21673 жёстко зашиты как "всегда доверенные" в нескольких местах (200 лет доступа вместо 3); APISAS.RESET_CODE сбрасывает доступ буквально только клиенту 2333 вне зависимости от параметра. → API-слой: APISAS_EFRONT

Единый предсказуемый пароль для всех аккаунтов внешней LMS Campus

APISAS_CAMPUS.USER_UPDATE_GETDATA возвращает константу '80295553238' как пароль для каждого синхронизируемого клиента. → API-слой: APISAS_CAMPUS

Публичные API-эндпоинты без какой-либо авторизации

Ни EFONLINE, ни worder_registration, ни процедуры Campus не проверяют токен, подпись или Basic-Auth. Единственная защита веб-заявок — один захардкоженный заблокированный IP (217.112.35.81) и словарь спам-слов. → API-слой, Клиенты: заявки с сайта

ADV_OBJECT_FINANCE.FIN_CREATE(vCLIENT_ID) — параметр игнорируется, фильтр жёстко CLIENT_ID = 2333. → Логистика: прочие пакеты

🟡 Рискованные решения и хаки

Скрипт как данные — диспетчеризация отчётов через EXECUTE IMMEDIATE

REV_EXEC.OnTaskProcess выполняет текст скрипта, хранящийся в таблице, а не в исходниках — архитектурная особенность, а не баг, но важно знать при отладке. → Отчёты

Три независимых способа внешней синхронизации в одной схеме

Heterogeneous DB link @EMS, HTTP-пинг на internal middleware, и явные ETL-таблицы — три поколения одной и той же задачи сосуществуют одновременно. → Маркетинг

Магические числа вместо конфигурации — повторяющийся паттерн во всей схеме

ID узлов каталога, категорий, товаров, пороги долга — зашиты прямо в SQL/PL/SQL десятками мест (CM_AC, WH, MS_PRINT, RECALCULATION и др.), а не вынесены в справочники или REV_CONST.

Два независимых источника ставки НДС для почтовых тарифов

POST_FEE_PKG — множитель 1.2 в формуле, POSTAL_RATE_CONTROL — константа 0.2. Нет единой точки истины. → Логистика: тарифы

Коллизия кодов операций в MONEY_DIST.TRANS_TYPE

mdOperAddMoneyReturn=91 совпадает с mdOperSetTicket=91 (аналогично 92/93) — одно числовое значение означает два разных типа операций из разных смысловых групп. → Финансы

Хрупкое кодирование бизнес-семантики строковой конкатенацией

CASE credit||debet WHEN '4070' ... и TO_CHAR(status||status_old) LIKE '6%' — без ELSE-ветки, ломается при появлении новых кодов справочника. → Отчёты, Финансы

⚪ Мёртвый и отключённый код

Автосоздание клиента из веб-заказа реализовано, но отключено

WEB_ORDER.AUTO_REG — рабочий код сопоставления/создания клиента, вызов закомментирован в проде. Все веб-заказы сегодня идут только через ручную очередь оператора. → Клиенты

Ручной SMS call-центр физически не может работать в современном браузере

REV_SMS генерирует VBScript/ActiveX для отправки через стороннее ПО на компьютере оператора — несовместимо с любым браузером, где отключён ActiveX (то есть с любым современным). Плюс вызовы удалённой из Windows команды net send. → Рассылки: call-центр

Рассылка сертификатов выпускникам не работает

CERTIFICATES_FOR_GRADUATES фиксирует событие о выпуске, но реальная отправка письма с сертификатом закомментирована с пометкой "нужно доп. тестирование". → Каталог курсов

Целая параллельная подсистема сообщений (MESSAGE_*) не подключена ни к чему

Билдеры контента, триггеры на PK — всё есть, но MESSAGE_BUILD.FLOW нигде не вызывается, кроме одного ручного предпросмотра. → Рассылки

Одна из трёх реализаций взыскания долга — CM_DEB — заброшена

Весь функционал, кроме двух тривиальных функций, закомментирован. → Маркетинг

ЕРИП: половина процедур интеграции — пустые заглушки

erip_upload/erip_ftp_export/erip_download/erip_import — тела BEGIN NULL; END;. → Финансы: ERIP

get_homework (eFront) валидирует и роняет данные

Реальная запись домашнего задания закомментирована — данные от eFront никуда не сохраняются. → Каталог курсов: eFront

EMESSAGE_SEND — осиротевший API

Ни одна процедура пакета нигде не вызывается во всём дампе — рассчитан на внешнее JSP-приложение, которого нет в этой схеме. → Рассылки

Пустые пакеты-заглушки и заброшенные дубли

ESCC_CLIENT — полностью пустой, несмотря на говорящее имя. REV_CONTACT хранит 4 полностью закомментированные старые процедуры рядом с рабочими. REV_REPORT — job_operationOLD и другие полные копии текущих процедур. → Клиенты, Отчёты

Как использовать эту сводку

Если готовите ревью безопасности или планируете миграцию — начните с раздела 🔴: это единственные пункты, которые касаются реальных данных клиентов и денег. Разделы 🟡/⚪ — скорее контекст для оценки объёма технического долга, чем немедленные действия.

Связанный, но отдельный контекст

У пары Laravel-приложений escc-service/escc-cabinet, которые читают эту Oracle-схему, есть свой независимый аудит безопасности (открытые PII-эндпоинты без авторизации, MD5-пароли, отключённый SSL) — он не входит в этот PL/SQL-документ, но напрямую связан с частью находок выше (например, отсутствие проверки авторизации в API-слое Oracle усугубляет то же самое на стороне Laravel).
