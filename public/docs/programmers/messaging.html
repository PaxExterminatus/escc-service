Домен 05Рассылки и сообщения

Три независимых, не связанных друг с другом канала связи с клиентом сосуществуют в одной схеме: очередь EMSG (её и читает наш Laravel-сервис), ручной call-центр с внешним SMS-гейтвеем на компьютере оператора, и низкоуровневая SMTP-библиотека для email "по требованию".

Для руководства
Что это простыми словами Автоматические SMS и email клиентам: напоминания о долге, информационные сообщения, уведомления об отправке посылки.
Состояниетребует срочного внимания Из всего, что для этого построено, реально работает только один сценарий — уведомление об отправке посылки. Автоматические напоминания о долге и информационные SMS технически существуют в системе, но ни к чему не подключены — то есть попросту не отправляются, хотя выглядят как рабочая функция. Отдельный старый инструмент для ручной отправки SMS через операторов, скорее всего, физически не работает уже много лет (завязан на технологию браузера, отключённую повсеместно с 2010-х).
Главный риск для бизнеса Если кто-то в компании считает, что клиентам сейчас автоматически напоминают о долге по SMS — это не так. Отдельно: при восстановлении пароля клиенту отправляется его реальный пароль в открытом виде по почте, а сами пароли хранятся и логируются на диск без защиты — прямой риск утечки учётных данных клиентов.
Главная находка домена

Единственное бизнес-событие, которое сегодня реально и без сбоев наполняет очередь EMSG в статусе, который читает Laravel (EMSG_STATUS=1) — это факт отправки посылки Белпочтой (плановая задача COMMUNICATION.ALERT_SEND_POST_BATCH → EMESSAGE_CREATE.BOX_SEND_POSTOFFICE). Остальные сценарии (задолженность, инфосообщения, коды доступа) технически реализованы, но не имеют ни одного вызывающего места в коде — это либо ручной триггер через внешний JSP на dev-хосте, либо заброшенный функционал.

Реальный конвейер EMSG

Таблица EMSG — очередь исходящих сообщений (EMSG_TYPE: 1=SMS, 2=EMAIL; EMSG_STATUS используется непоследовательно, см. ниже). Наш Laravel-сервис читает её через view API_MESSAGES_SMS_DAILY (EMSG_TYPE=1 AND EMSG_STATUS=1) — сам её не наполняет.

EMESSAGE_CREATE
таблицы: EMSG_STREAM, EMSG, BATCH_SCHEMA_SEND
ПроцедураЧто делает
STREAM(cause, client, ...)Причины 3=долг/4=инфо/5=коды доступа → EMSG_STATUS=3 (не подхватывается Laravel-view!)
BOX_SEND_POSTOFFICEЕдинственный живой путь: массовый INSERT по клиентам, кому сегодня отправлена посылка, EMSG_STATUS=1 — именно это читает Laravel
Два конвейера с разной семантикой статуса

STREAM ставит EMSG_STATUS=3, BOX_SEND_POSTOFFICE — =1. Это фактически два независимых, не согласованных друг с другом способа наполнения одной таблицы.

EMESSAGE_CONTENT

Генерация текста для причин долг/инфо/коды — тексты захардкожены прямо в PL/SQL, отдельной таблицы шаблонов нет. Выбор кодировки (PRM_SMSCOUNT) — минимизирует число SMS-частей (GSM7 транслит vs UNICODE кириллица), то есть оптимизирует по стоимости отправки.

Хардкод в тексте сообщений

Номера горячей линии оператора связи (MTS +375296910330) зашиты прямо в текст SMS.

EMESSAGE_SEND

Вопреки названию — не отправляет сообщения (нет ни UTL_HTTP, ни UTL_SMTP). Только отдаёт курсор на неотправленные (STREAM_DATA) и принимает callback от внешнего шлюза (SMS_REPLY_* → EMSG_REPLY_HTTP/SERVICE).

Осиротевший API

Ни одна процедура этого пакета нигде не вызывается во всём дампе — рассчитан на вызов из внешнего JSP-приложения, которого нет в этой схеме. Закомментированная EMAIL_ACTIVECAMPAIGN — старая попытка интеграции с ActiveCampaign через database link @EMS, полностью отключена.

EMESSAGE_GUI

Генератор ссылок для карточки клиента ("отправить сообщение" → внешний JSP).

Dev-хост в проде

Константа APP_HOST := 'dev.office.eshko.net:8282' зашита прямо в теле пакета — если это боевая схема, все ссылки "отправить сообщение" в GUI ведут на dev-окружение.

Заброшенная альтернатива: подсистема MESSAGE_*

Параллельно с EMSG существует отдельный, более общий набор таблиц (MESSAGE, MESSAGE_FLOW, MESSAGE_TEMPLATE, MESSAGE_CAUSE) и обслуживающих их пакетов — судя по всему, недостроенная попытка заменить EMSG.

MESSAGE_BUILD · MESSAGE_BUILD_DATA · MESSAGE_SYSTEM_TRG

MESSAGE_BUILD.FLOW должен по причине (account_debt, info_client, access_efront, send_lesson) собирать сообщение через MESSAGE_BUILD_DATA.DEBT_SMS/INFO_SMS/ONLINE_ACCESS_SMS и класть в MESSAGE_FLOW (обслуживается триггером из MESSAGE_SYSTEM_TRG).

Полностью неактивная цепочка

MESSAGE_BUILD.FLOW нигде не вызывается во всём дампе, кроме одного ручного вызова PREVIEW из веб-админки (сценарий bill_course). Ветка send_lesson даже не заполняет данные. Раз FLOW не вызывается — триггер MESSAGE_FLOW_TRG тоже фактически никогда не срабатывает. Оба билдера контента (старый EMSG и этот новый) используют общий вспомогательный GETDATA.CLIENT_COMMUNICATION — единственная точка пересечения двух поколений.

REV_SMS — ручной call-центр (отдельный от EMSG)

REV_SMS
~4000 строк. Своя таблица SMS (не EMSG!), CLIENT_EVENT, BLACK_NUMBER, REGISTRY_FOLDER

Административный UI телемаркетинга поверх собственной таблицы SMS — операторы вручную отправляют/принимают SMS в рамках "событий контакта", с балансировкой нагрузки между операторами (CheckAddTelemarketingSMS) и блэклистом номеров.

Отправка происходит в браузере оператора, не на сервере

Функции пакета генерируют VBScript/ActiveX-код (CreateObject("AxSmsServer.MessageDB")) прямо внутри HTML-ответа — реальная отправка идёт через стороннее модемное ПО на компьютере оператора, таблица SMS в Oracle лишь зеркало. Это несовместимо с любым современным браузером (ActiveX отключён везде, кроме legacy IE) — весь механизм, скорее всего, физически не работает уже много лет.

net send — удалённая из Windows команда

sms_wait_notice вызывает WScript.Run("net send ...") для всплывающего окна у оператора — команда Messenger Service удалена из Windows начиная с Vista/2008.

REV_EMAIL — SMTP-библиотека "по требованию"

REV_EMAIL

Самодостаточная синхронная SMTP-библиотека (доработанный демо-пакет Oracle) — mail, mail_attach, mail_html. Вложения скачиваются по HTTP и заливаются в письмо base64. Вызывается напрямую из бизнес-кода (например, из REV_WEB_REQUEST при восстановлении пароля), в обход EMSG.

Пароль SMTP в открытом виде в исходнике

Прямо в спецификации пакета: smtp_host := '10.20.36.64'; smtp_login := 'action@eshko.pro'; smtp_password := 'fffa75Ms1'; — виден всем, у кого есть доступ на чтение исходников схемы.

mail_html отправляет пустое тело

Строка фактической записи данных вложения закомментирована — mail_html/attach_html в текущем виде отправляют письмо с пустым HTML-телом.

REV_WEB_REQUEST — приём заявок и авторизация с сайта

REV_WEB_REQUEST

Обработчик XML/CGI-запросов от сайта: заказы, регистрация/авторизация в кабинете, приём ДЗ. Единственная связь с рассылками — прямой вызов rev_email.mail_attach при восстановлении пароля.

Пароли в открытом виде — самая заметная находка домена

client.client_password хранится и сравнивается как обычная строка, без хеширования. Восстановление пароля отправляет реальный пароль по email в теле письма. Все параметры запроса, включая пароли, построчно логируются в текстовый файл log_YYYYMMDD.txt на диске — компрометирующий журнал открытым текстом.

Схема пути сообщения

Верхняя строка (акцент) — единственный реально работающий путь. Нижняя строка (пунктир) — технически существующая, но не подключённая ни к чему ветка.
