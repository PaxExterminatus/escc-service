Домен 03Каталог курсов и обучение

Структура каталога курс→уроки, расчёт цены курса из цены его уроков, отслеживание прогресса и финансового состояния подписки — и отдельная HTTP-интеграция, которая выдаёт права доступа к онлайн-урокам во внешней LMS eFront.

Для руководства
Что это простыми словами Из чего состоят курсы (уроки, цена), и как ученик получает доступ к онлайн-уроку на внешней образовательной платформе eFront.
Состояниетребует срочного внимания Каталог и цены считаются корректно. Но проверка кода доступа к целому курсу в интеграции с eFront сейчас отключена — принимается любой введённый код. Также обнаружено, что письма с сертификатом об окончании курса выпускникам сейчас не отправляются, хотя факт выпуска в системе фиксируется.
Главный риск для бизнеса Отключённая проверка кода — это дыра в платном доступе к контенту (в теории, курс можно открыть без настоящего кода). Отсутствие сертификатов — тихий пробел в клиентском опыте: система думает, что всё в порядке, а выпускники писем не получают.

CRS_PKG_UTILS — расчёты по курсу

CRS_PKG_UTILS
таблицы: CLIENT_SUB, CONTAINER, CLIENT_BASKET, PRODUCT_CATEGORY, CATEGORY, CLIENT_EVENT_LOG, CLIENT_SUB_STATUS_LOG, RETURN_ITEM

Утилиты расчётов по подписке (SUB_ID/ITEM_ID): выставлено/получено/возвращено/ потеряно по контейнерам (CRS_INVOICED_SUM, CRS_RECEIVED_SUM, CRS_RETURNED_SUM, CRS_LOST_SUM), последний статус подписки на дату (GET_COURSE_LASTSTATUS), последний отправленный номер "блока" (GET_UNIT/GET_REMAINS_UNIT) — по кодам категорий-счётчиков "Unit N".

REV_CATALOGUE — админка каталога

REV_CATALOGUE
~5300 строк тела — самый крупный пакет домена. Таблицы: CATALOGUE, CATALOGUE_CONTENT, CATEGORY, PRODUCT_CATEGORY, CHANNEL, TAX_TYPE/STATUS, OFFER, REGISTRY_FOLDER

Backend админ-панели каталога: полный CRUD категорий, каналов, налогов, офферов, товаров/курсов.

Ключевая бизнес-функция

catalogue_price_calculate(itemID) — цена курса (goodTypeComposite) не хранится независимо, а вычисляется как пропорциональное перераспределение заданной цены курса по ценам входящих в него уроков/услуг (дерево CATALOGUE_CONTENT), с округлением через ROUND_MONEY и списанием остатка округления на последний элемент — классическая схема "цена комплекта = сумма позиций" без дрейфа округления.

Встроенный конструктор SQL в админке

Блок tuner_* (tuner_sql_select/update/run) — встроенный конструктор произвольных SQL-отчётов с сохранением профилей. Мощный, но и рискованный инструмент — доступ к произвольным данным через админку, стоит учитывать при аудите прав доступа.

ONLINE_EDUCATION — собственные PIN-коды

ONLINE_EDUCATION
таблица: ONLINE_ELEMENT_ACCESS

Отдельная (не eFront) система PIN-кодов доступа к онлайн-материалам: при отправке посылки ACCESS_CREATE_ROW создаёт запись доступа — один PIN на весь курс (продажа "полным комплектом") или PIN на каждый урок (продажа "по блокам"). RTDATA_CLIENT_CURSES строит XML со статусом доступа: доступ закрывается, если урок не отправлен >30 дней, был возврат, или не покрыт оплатой.

Незавершённая/заброшенная альтернатива

CHK_PIN_CURS и CHK_PIN_LESSON — пустые заглушки (BEGIN NULL; END;), несмотря на то что вызываются из диспетчера. Похоже, эту собственную PIN-систему вытеснила связка APISAS_EFRONT + CLIENT_SUB_ONLINE_ACCESS ниже.

APISAS_EFRONT — интеграция с eFront

APISAS_EFRONT
таблицы: API_EFRONT_DATA, CLIENT_SUB_ONLINE_ACCESS, CLIENT_SUB_ONLINE_ERROR, CLIENT_SUB_ONLINE_LOG

Реальный мост к внешней LMS eFront — вызывается напрямую по HTTP (mod_plsql/OWA). Точка входа: EFONLINE(cl_code, rq_type, rq_code, node_id, lesson_item).

Механизм — "почтовый ящик" в таблице, а не прямой ответ: старый ответ клиента удаляется (DELETE FROM API_EFRONT_DATA WHERE CLIENT_ID=...), считается новый XML по типу запроса (data=список курсов, code=проверка кода доступа, reset=сброс), результат конвертируется в BLOB и одним INSERT кладётся обратно в ту же таблицу — включая случай ошибки (даже exception результируется строкой в этой же таблице, а не пробрасывается наружу).

Важно для нашей интеграции

API_EFRONT_DATA — не пассивный кэш, а результат последнего запроса. Строка появляется/обновляется только когда eFront реально вызвал EFONLINE для этого клиента. Никакого фонового обновления/TTL нет — для клиента, который давно не заходил в eFront, строки может не быть вовсе либо она устаревшая.

Отключена проверка кода доступа к курсу

В getonlineaccesscourse реальное сравнение заменено константой: IF TRUE THEN --access-px [online_acc_code = acc_code] — любой код доступа к курсу принимается как верный. Для урока (getonlineaccesslesson) проверка осталась настоящей — непоследовательность между курсом и уроком.

Тестовые аккаунты с вечным доступом в проде

ID 2333 и 21673 жёстко зашиты как "тестовые клиенты" — им выдаётся доступ на 200 лет вместо обычных 3.

get_homework — принимает и роняет данные

Процедура валидирует пришедшее от eFront ДЗ (work_id, оценки, даты)... и ничего не сохраняет — реальный INSERT закомментирован, возвращается просто "1"/"0".

Прочие пакеты домена

CATALOGUE_PKG_UTILS

Классификатор узла каталога: онлайн/PDF-товар по коду категории, привязка PDF-курса к печатному через CATALOGUE_ADDONS (5 слотов addon1..addon5).

CERTIFICATES_FOR_GRADUATES

Плановое задание: находит выпускников (курс полностью оплачен, дата окончания в интервале) и помечает событием "отчислен по окончании".

Рассылка сертификатов отключена

Блок реальной отправки письма с сертификатом закомментирован; вместо него — task.UPDATELOG('Добавления писем ОТКЛЮЧЕНО. Нужно дополнительное тестирование'). Физическая отправка сертификата выпускникам не работает, фиксируется только событие в CRM.

rev_web_learning

Один метод get_category — проверка принадлежности контейнера списку категорий, с особым правилом для сборных/разноуровневых курсов (категория SPLIT/C043).

GAMES_ESHKO

Не про обучение — ETL для маркетинговой акции-розыгрыша по веб-заказам: отсеивает "мусорные" заявки (телефон не по маске, тестовый email, латиница в ФИО) перед розыгрышем призов. ESHKO — название бренда компании, не "игры для учеников".

Жизненный цикл прохождения курса

Пунктирная линия к "сертификату" — переход декоративный: событие о выпуске фиксируется, но письмо с сертификатом сейчас не отправляется (см. находку выше).
